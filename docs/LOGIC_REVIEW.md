# 逻辑检查与优化记录

日期：2026-10-26。检查范围：画布、关系验证/发现、项目隔离、快照与项目生命周期。不是完整安全审计。

## 本轮已修复

1. 从画布移除表原先会删除 USER_DEFINED/BUSINESS 关系。现在只移除布局节点，分析结论继续保留。
2. 确认、忽略、删除、批量处理关系原先忽略 URL projectId。现在校验关系所属工作区，批量请求先完整校验，防止部分越项目写入。
3. 添加/保存画布和验证/创建关系原先接受其他项目或旧快照的表字段。现在限制为当前项目活动快照。
4. 同一对字段正反方向重复连线会重复保存。现在对非忽略关系进行双向重复检查；并发重复仍需数据库约束进一步保证。
5. 保存空画布原先直接返回旧布局，现在空数组会清空布局，null 请求拒绝。
6. 切换项目时重置 Schema、选择、详情缓存和画布状态。
7. 离开画布或切换项目时取消待执行的延迟保存；移除表时也取消待保存任务；删除失败的表不会从持久状态中误移除。已发出的异步请求尚需统一取消/版本控制。

## 后续优先级

### 高：快照继承及活动范围

MetadataService.pullSnapshot 创建新表字段 ID 后切换 activeSnapshotId，没有迁移画布、人工备注及关系。getCanvas/listRelations 仍按 workspace 返回，可能混入旧快照成果。本轮新增写入校验会拒绝旧对象，但尚未实现刷新继承，应先实现按结构身份匹配的迁移及删除/改名冲突报告。跨 Schema 外键目前在每个 Schema 内采集，后采集 Schema 的目标表可能尚未建立索引，导致外键漏采；应拆为全结构采集、全外键解析两个阶段。

### 高：自动关系发现的漏报与评分

RelationDiscoverService.scoreInclusion 仍比较两份独立样本，前一轮的全表存在性修复仅用于手工连线及确认。自动发现可能漏掉正确关系，也可能将偏差样本作为评分依据。建议候选生成与证据验证分开：按类型/主键/名称等召回候选，针对候选单侧抽样查对方全表，加入父侧唯一性和异常值。不能只对现有入围结果复核，否则样本筛选阶段漏掉的关系仍找不回。需有查询预算、缓存、任务取消，避免全字段笛卡尔查询。

### 高：项目删除和数据源生命周期

ProjectService.delete 只删 project，未级联清理 workspace、快照、表字段、关系、画布。需要事务化删除链及失败回滚测试。项目更新可以直接更换数据源，旧快照和画布仍对应旧库，需要显式迁移/新建分析的策略。数据源删除保护当前仅检查项目绑定，不覆盖遗留快照。

### 中：异步状态和性能

AnalysisPage.refresh 对多个 API 错误返回空数组，会掩盖网络/服务错误；应区分未采集与加载失败。项目切换后的迟到响应可能写回全局 store；需要请求取消和项目版本检查。画布保存请求也需要版本控制，避免旧请求覆盖新位置。

toView 逐关系查询表字段，关系多时形成 N+1 查询；应批量加载映射。采集为逐表多连接，同步事务包裹远程数据库访问，规模大时延迟及 SQLite 锁占用较高；建议后台任务及分阶段提交。

### 中：通用类型语义

全表存在性查询当前依靠 JDBC 字符串绑定、数据库比较与 Java 文本集合归一化。大小写不敏感排序规则、定长 CHAR、数值跨类型格式可能产生差异。需要明确“数据库相等”还是“规范化文本相等”，增加 Oracle/MySQL 真机类型回归。
